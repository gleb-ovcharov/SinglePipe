# Архитектура и стиль кода SinglePipe

Документ фиксирует, **как устроены типы в SinglePipe и почему**. Если новый код расходится с этими правилами, меняется либо код, либо документ, но осознанно и с записью причины.

Статусы решений:

- **Принято** — действует, новый код пишется так.
- **Цель** — направление согласовано, существующий код ещё не переведён.
- **Открыто** — решения нет, варианты описаны.

---

## 1. Три вида объектов

Любой класс в библиотеке относится к одному из трёх видов. От вида зависит, от чего наследоваться.

| Вид | Что это | Примеры | Основа |
|---|---|---|---|
| **Запись** | Данные с полями: валидируются, сериализуются, отдаются в FastAPI | `BBox`, `Prediction`, `Detection`, выходы задач | `pydantic.BaseModel` |
| **Значение или контейнер** | Объект со своим поведением, которому от pydantic нужно только одно: лежать в поле модели и валидироваться | `Image`, `PredictionList[T]` | Обычный класс + `__get_pydantic_core_schema__` |
| **Контракт** | Что адаптер требует от схемы задачи | `InputSchema`, `OutputSchema` | `BaseModel` + `abc.ABC` |

**Вопрос-проверка:** «является ли это *записью данных*?» Если да — `BaseModel`. Если это *значение* (картинка, коробка-вычислитель, коллекция), то наследование от `BaseModel` принесёт чужой интерфейс (`model_dump`, `copy`, `json`, свой `__iter__`), который будет мешать.

Статус: **Принято.** Основы написаны: `primitives.py` (`BBox`, `Prediction`, `Detection`), `modalities/image.py` (`Image`), `containers.py` (`PredictionList`). Схемы задач на них ещё не переведены.

### 1.1. Записи — `BaseModel`

- Предсказания и их части неизменяемы: `model_config = ConfigDict(frozen=True)`.
- Методы, которые «меняют» объект, возвращают новый через `type(self)(...)` и аннотируются `-> Self`. Так наследники сохраняют свой тип.
- Поведения в записях минимум: геометрия у `BBox` уместна, логика коллекций — нет (см. 1.2).

### 1.2. Значения и контейнеры — обычный класс

Механизм pydantic v2 для собственных типов — классметод `__get_pydantic_core_schema__`. Класс описывает, как себя валидировать и сериализовать, и после этого используется как тип поля:

```python
class Image:
    __slots__ = ("pil",)

    def __init__(self, source: Any) -> None: ...   # нормализация входа

    @classmethod
    def __get_pydantic_core_schema__(cls, source, handler):
        return core_schema.no_info_plain_validator_function(
            cls, serialization=core_schema.plain_serializer_function_ser_schema(...)
        )


class ImageClassificationInput(BaseModel):
    image: Image          # валидация работает, ValueError превращается в ValidationError
```

Правила:

- Неизменяемость вручную: `__slots__`, без сеттеров; `__eq__`/`__hash__` — если нужны.
- Сериализатор и JSON-схему (для FastAPI) класс определяет сам.
- Ошибка входа — `ValueError` (см. раздел 5).

**Коллекции** наследуют `collections.abc.Sequence`: реализуются `__getitem__` и `__len__`, а `__iter__`, `__contains__`, `__reversed__`, `index`, `count` приходят бесплатно. Это ABC в роли примеси.

Итерация, `len`, `in`, индексация — поведение **контейнера** (`out.predictions`), а не записи-выхода (`out`).

## 2. Контракт схем задач

Статус: **Принято.** Реализован в `singlepipe/schemas/contract.py`; схемы задач и реестр на него ещё не переведены.

Адаптер знает о задаче только через контракт:

| Класс | Члены |
|---|---|
| `InputSchema[T_co]` | абстрактные `from_raw(cls, raw: object) -> Self` и `to_pipeline_input(self) -> T_co`; свойство `output_context -> Mapping[str, Any]`, по умолчанию `{}` |
| `OutputSchema` | абстрактный `from_pipeline_output(cls, raw: Any, **context: Any) -> Self` |
| `ensure_implements(schema, contract)` | проверка при регистрации: передан класс, он наследует контракт, абстрактных методов не осталось; иначе `TypeError` с объяснением |

Решения:

- **Контракт наследует `BaseModel` и `abc.ABC`.** Библиотека всегда валидирует данные, поэтому схема без pydantic невозможна, а пользователь наследует одну базу: `class MyInput(InputSchema[str])`. Конфликта метаклассов нет: метакласс pydantic наследует `ABCMeta`. Плата: схему на dataclass или attrs сделать нельзя.
- **Пользовательская схема обязана наследоваться от контракта**, как `nn.Module` в PyTorch или `BaseEstimator` в scikit-learn.
- **Проверка `inspect.isabstract` при регистрации обязательна.** `@abstractmethod` запрещает только создание объекта; забытый абстрактный *классметод* (`from_raw`) при вызове молча вернёт `None`, и ошибка всплывёт глубоко в адаптере.
- **`output_context` не абстрактный**, по умолчанию пустой: пустой контекст — нормальный случай. Пересмотреть, если появятся задачи, где забытый контекст станет частой ошибкой.
- **`__subclasshook__` не используем.** Он проверяет только имена методов, не сигнатуры и не смысл; в stdlib его применяют лишь в ABC с одним методом (`Sized`, `Iterable`).
- **Виртуальные подклассы (`register()` у ABC) не используем**: pydantic отключает их для своих моделей, а на обычных ABC они объявляют совместимость без проверки.
- **`Protocol`** не нужен, пока контракт выражается через наследование.
- **`Any` только на границах с нетипизированным кодом:** сырой ответ бэкенда в `from_pipeline_output` и значения `output_context` (кандидат на `TypedDict` по задачам, когда задач станет больше).

### 2.1. Вариантность

Правило: **отдаёшь — ковариантно, принимаешь — контравариантно, и то и другое — инвариантно.**

- **`T_co` в `InputSchema` ковариантен** (`covariant=True`, суффикс `_co`): контракт тип только возвращает, поэтому `InputSchema[Cat]` подходит туда, где ждут `InputSchema[Animal]`. mypy не даст использовать такую переменную как тип параметра.
- **Переопределение методов подчиняется принципу Лисков:** параметры можно только расширять, возвращаемый тип — только сужать. `from_raw(raw: object)` нельзя сузить до `raw: str` — это гарантия, что любая схема принимает любое значение и сама решает, валидно ли оно. `to_pipeline_input` в наследнике может вернуть более узкий тип.
- **Только для чтения — абстрактные типы коллекций:** `Mapping` вместо `dict`, `Sequence` вместо `list` в аннотациях. `dict` и `list` инвариантны, потому что в них можно писать; `Mapping` и `Sequence` ковариантны.
- **`Predictions[T_co]` — ковариантный `Sequence`**, поэтому одна функция для `Predictions[Prediction]` принимает предсказания любой задачи. С `list[Detection]` это не работает: `list` инвариантен.
- **`type[...]` ковариантен:** `type[TextInput]` подходит туда, где ждут `type[InputSchema[Any]]`; на этом держится типизация реестра.
- **Контравариантность появится в аргументах-функциях:** `Callable[[T], bool]` контравариантен по аргументам, поэтому предикат для любого `Prediction` годится для фильтра детекций.

## 3. Сосуществование с pydantic

Статус: **Принято.**

`BaseModel` уже занимает имена. Перекрыть их — значит молча сломать pydantic (так было с `__iter__`, который ломал `dict(model)`).

**Нельзя определять в наследниках `BaseModel`:**

- dunder-методы: `__iter__`, `__eq__`, `__hash__`, `__getattr__`, `__copy__`;
- публичные имена: всё с префиксом `model_*`, а также наследие pydantic v1: `copy`, `dict`, `json`, `schema`, `schema_json`, `validate`, `construct`, `parse_obj`, `parse_raw`, `parse_file`, `from_orm`, `update_forward_refs`.

**Свободны** (у `BaseModel` их нет): `__len__`, `__getitem__`, `__contains__`, `__bool__`. Но по правилу 1.2 коллекционное поведение живёт в контейнере, а не в записи.

**Страховка:** тест проходит по всем нашим базовым классам и примесям и падает, если какой-то атрибут перекрывает атрибут `BaseModel`. *Цель.*

## 4. Примеси

Статус: **Принято** как правило; сейчас не применяются.

Примесь уместна, когда возможности **комбинируются**: у одних задач есть, у других нет (пример из scikit-learn: `ClassifierMixin`, `TransformerMixin`). Пока задачи две и возможности у них одинаковые, достаточно одного generic-контейнера `Predictions[T]`.

Правила для будущих примесей:

- без полей и без состояния;
- в списке баз стоят **перед** `BaseModel`;
- работают только через публичные атрибуты хозяина (например `self.predictions`);
- подпадают под запрет имён из раздела 3.

---

## 5. Ошибки

Статус: **Принято.**

- Любой некорректный вход (неподдерживаемый тип, неверная форма массива, нечитаемые байты или файл) → `pydantic.ValidationError`.
- Внутри валидаторов бросаем **`ValueError`**, не `TypeError`: pydantic оборачивает только `ValueError` и `AssertionError`, остальное вылетает наружу как есть.
- Ошибки PIL и файловой системы (`OSError` и наследники) перехватываются и превращаются в `ValueError` с указанием источника.
- Сетевые и HTTP-ошибки при загрузке URL остаются исключениями `httpx`: это проблема сети, а не данных пользователя.

## 6. Предсказания

- **Иерархия** *(Принято)*: база `Prediction` (`label`, `score`, `label_id`); `Detection(Prediction)` + `box: BBox` — детекция *является* предсказанием и *имеет* коробку. Отдельного `Classification` нет: пустой наследник был бы вторым именем для `Prediction`. Общая логика (`top`, `top1`, `labels`, `filter`, `filter_by_score`, `filter_by_label`) — один раз в `PredictionList[T_co]`. Наследник вроде `DetectionList` заводится, только когда появляется операция, которой нужны коробки (`clip`, `nms`).
- **`score` — вероятность в [0, 1]**, а не логит. Бэкенд, который выдаёт логиты, нормализует их сам. *Принято.*
- **`score=None` означает «бэкенд не дал уверенности»**, а не «уверенность низкая». Любая операция, опирающаяся на скор (`top`, `top1`, `filter_by_score`), падает с `ValueError`, если хотя бы у одного предсказания скора нет. Проверка — в одном месте. *Принято.*
- **Сортировка стабильна:** при равных скорах сохраняется порядок бэкенда. *Принято.*
- **Строка в `filter_by_label` — одна метка**, а не набор символов. *Принято.*

## 7. Когда выносить общее

Статус: **Принято.**

- Выносим только то, что **уже одинаково** минимум в двух реальных задачах. Абстракция, выведенная из одного примера, почти всегда оказывается неверной.
- Базовым классам — конкретные имена по смыслу (`ImageTaskInput`, `Predictions[T]`), а не `BaseInput`/`BaseOutput` «для всех 30 задач».
- Заглушки задач с `NotImplementedError` не держим: семантику задач хранит `TaskType`, реализацию — реестр.

---

## 8. Сериализация

Статус: **Принято — отложено.**

Внутри одного процесса объекты между узлами графа не копируются, передаются ссылки. Сериализация памяти не экономит, а тратит её. Своя сериализация понадобится на границе процессов или машин (async, remote-бэкенды) и для кэша. До тех пор хватает `model_dump`/`model_dump_json`; для типов-значений сериализацию описывает сам тип (раздел 1.2).

---

## 9. Тесты

Статус: **Принято.**

- Структура `tests/` повторяет структуру пакета.
- **Юнит-тесты** — без моделей, файлов и сети: картинки создаются в памяти, HTTP подменяется.
- **Интеграционные** — `tests/integration/`. Крошечная модель со случайными весами собирается прямо в тесте и проверяет стыковку с настоящим pipeline HF без сети. Настоящие предобученные модели помечаются `@pytest.mark.slow` (`pytest -m "not slow"` — быстрый прогон).
- **Сначала тесты, потом рефакторинг.** Тесты фиксируют поведение; при переносе кода в базовые классы они должны остаться зелёными без изменений.
- Известный баг или нерешённое поведение — `@pytest.mark.xfail(strict=True, reason=...)`. Когда проблему исправят, `strict` заставит снять пометку.
- Тест проверяет поведение, а не устройство: имена полей NamedTuple, приватные методы и т.п. в тестах не фигурируют.

```
Записи (BaseModel)          BBox                                     primitives.py    ✓

Схемы задач                 ImageTaskInput(InputSchema[PILImage.Image])
  (наследуют контракт)        ├─ ImageClassificationInput
                              └─ ObjectDetectionInput  (+ output_context с размерами)
                            ImageClassificationOutput(OutputSchema)
                              predictions: PredictionList[Prediction]

                              predictions: PredictionList[Detection], image_width, image_height
```

Порядок перехода:

1. ~~Контракт `InputSchema`/`OutputSchema`, `ensure_implements`~~ — сделано.
2. ~~Примитивы `BBox`, `Prediction`, `Detection`~~ — сделано.
3. ~~`Image` → обычный класс с хуком pydantic~~ — сделано.
4. ~~`PredictionList[T_co]`~~ — сделано.

## 11. Открытые вопросы

- **Обязательность `score` в `Prediction`.** Сейчас у `Detection` он обязательный, у `Classification` — опциональный. Предложение: опциональный везде (политика раздела 6 уже это покрывает). Альтернативы: переопределять в `Detection` как обязательный или сделать обязательным везде.
- **`BBox.clip` для коробки целиком вне картинки.** Сейчас обрезка даёт вырожденную коробку, и валидатор падает с `ValidationError`. Варианты: возвращать `None` или бросать понятную ошибку.
- **`label_id`.** Поле есть, адаптер его не заполняет. Источник — `pipe.model.config.label2id`. Тест `test_label_id_is_not_filled_yet` фиксирует текущее поведение.
- **JSON-схема `Image` для FastAPI.** Сейчас Swagger показывает пустой объект; решается вместе с переводом `Image` на обычный класс.
- **Реестр и пользовательские задачи.** Ключ реестра — `TaskType`, а `StrEnum` нельзя дополнить снаружи: пользователь может только перезаписать схемы встроенной задачи, но не добавить свою. Плюс `get_schemas` теряет тип: mypy не знает, какой выход вернёт адаптер. Варианты: ключ `TaskType | str`; задача как объект `Task[In, Out]`, который сам несёт схемы (снимает и проблему ключа, и потерю типа, но меняет `TaskType`). Решаем перед Connector; до тех пор реестр не трогаем.
